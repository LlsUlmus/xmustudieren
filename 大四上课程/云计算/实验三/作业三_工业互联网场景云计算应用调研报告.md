# 工业互联网场景下的云计算应用调研报告

## 引言

实验二对阿里云、腾讯云、华为云、AWS、Azure、Google Cloud 及 Heroku 七家厂商的应用级 PaaS 服务进行了功能与实践对比，得到了"容器级 PaaS 是主流趋势""国内厂商侧重企业级治理、国外厂商侧重开发者体验""供应商锁定风险需纳入选型考量"等结论。本报告在此基础上，聚焦**工业互联网**这一具体应用场景，从需求侧、市场侧、技术侧三个维度展开调研，并将实验二中的 PaaS 对比结果延伸到工业互联网场景下，考察各云厂商 PaaS 及其配套的工业互联网专属能力能否满足该场景的实际需求。

工业互联网是新一代信息通信技术与工业经济深度融合形成的新型基础设施、应用模式和工业生态，其核心是通过全要素、全产业链、全价值链的连接，实现设备、产线、工厂、供应商、产品、客户之间数据的深度感知、动态监测与信息交互，进而推动制造业向数字化、网络化、智能化转型。在我国"新基建"与"制造强国"战略中，工业互联网被列为重点方向之一。

## 一、需求调研

### 1.1 政策与产业背景

2021 年，工业和信息化部印发《工业互联网创新发展行动计划（2021—2023 年）》，提出到 2023 年在网络、标识、平台、安全等重点领域实现关键技术突破，工业互联网标识解析体系覆盖国民经济重点行业 [4]。2024 年 2 月，工业和信息化部等十二部门进一步印发《工业互联网标识解析体系"贯通"行动计划（2024—2026 年）》，推动标识解析体系向千行百业深度渗透 [5]。政策的连续性表明，工业互联网已从"平台建设"阶段进入"规模化应用与产业融通"阶段，云计算 PaaS 平台作为承载工业应用的核心基础设施，其重要性随之提升。

据中国信息通信研究院测算，2024 年我国工业互联网核心产业规模已达 1.53 万亿元，渗透带动的产业增加值达 3.48 万亿元，同比增长 4.7%；产业预计将保持年均约 13% 的增速，到 2026 年规模突破 2 万亿元 [1][3]。产业规模的持续扩张，反映出制造企业数字化转型需求正在从"要不要做"转向"如何做好"。

### 1.2 制造业数字化转型的核心痛点

结合行业调研与公开资料，制造企业在推进工业互联网建设时普遍面临以下痛点：

1. **设备联网难。** 产线设备品牌、年代、通信协议（OPC UA、Modbus、PROFINET、CAN 等）差异巨大，老旧设备缺乏数字接口，异构协议的统一接入和标准化改造成本高。
2. **数据孤岛。** OT（运营技术）系统与 IT 系统长期独立建设，MES、ERP、SCADA 等系统之间数据不互通，难以形成全局数据视图。
3. **生产可视化与效率管控不足。** 缺乏实时、跨产线的生产状态监控手段，异常发现与响应滞后，影响良率与交付周期。
4. **预测性维护缺失。** 设备维护仍以定期检修或故障后维修为主，非计划停机造成的产能损失和维修成本较高，缺乏基于振动、温度、电流等多源数据的健康度预测能力。
5. **供应链协同弱。** 尤其是中小配套企业信息化基础薄弱，与核心企业之间的订单、库存、物流数据难以实时同步，产业链协同效率低。
6. **能耗与碳管理压力。** "双碳"目标下，企业需要对能耗、碳排放进行精细化计量与优化，但相关数据采集与分析能力普遍不足。
7. **安全可信要求高。** 工控系统一旦联网即面临网络攻击风险，同时涉及生产工艺等核心商业机密，对数据出境、等级保护、身份认证等安全合规要求远高于一般互联网应用。

### 1.3 典型需求场景与技术能力映射

| 需求场景 | 业务诉求 | 对应技术能力 |
|---|---|---|
| 设备联网与数据采集 | 异构设备统一接入、协议转换 | IoT 设备管理平台、边缘网关 |
| 边缘实时处理与产线控制 | 低时延、高可靠、弱网可用 | 边缘计算、边缘容器/规则引擎 |
| 工业大数据存储与分析 | 海量时序数据存储、跨系统数据打通 | 时序数据库、流计算、数据中台 |
| 数字孪生与仿真 | 虚实映射、工艺仿真、可视化 | 三维建模引擎、知识图谱、数字孪生 PaaS |
| 预测性维护与质量检测 | 设备健康度预测、缺陷视觉检测 | 机器学习平台、工业视觉 AI |
| 低代码工业 APP 开发 | 快速搭建 MES/能耗/看板类应用 | aPaaS、低代码开发平台 |
| 供应链协同与产业链金融 | 订单、库存、物流数据共享 | 企业级 SaaS、开放 API、区块链存证 |

### 1.4 用户画像与差异化需求

- **大型制造集团**（家电、装备、汽车、钢铁等）：已具备一定信息化基础，对定制化程度、数据主权、系统集成深度要求高，倾向于"通用云基础设施 + 自建或深度定制工业互联网平台"的混合模式。
- **中小企业**：信息化基础薄弱、IT 团队有限，更看重开箱即用、按需付费、实施周期短的 SaaS 化能力，价格敏感度高。
- **装备与设备制造商**：希望从"卖设备"向"卖设备+服务"转型，需要远程运维、设备联网管理等能力反哺自身产品竞争力。
- **区域/园区运营方**：承担区域工业互联网平台建设任务，关注平台的多租户能力、行业模板复用能力及与地方产业政策的适配性。

## 二、市场调研

### 2.1 市场规模与增长趋势

如前所述，2024 年我国工业互联网核心产业规模约 1.53 万亿元，预计 2026 年将突破 2 万亿元，年均增速约 13% [1][3]。这一增速显著高于传统 IaaS/通用 PaaS 市场的增速，说明工业垂直场景正成为云计算厂商新的增长点。

### 2.2 竞争格局

国内工业互联网平台市场呈现"平台林立、头部集中"的特点，工业和信息化部持续遴选的"双跨"（跨行业跨领域）平台中，代表性厂商可分为三类：

- **云计算厂商系**：阿里云 supET（及其孵化的犀牛智造）[6][7]、腾讯云 WeMake（整合了云产品、优图工业 AI、微瓴 IoT 等能力，截至 2024 年 6 月已覆盖 22 个工业细分领域、服务 68 万家企业）[9]、华为云 FusionPlant（依托鲲鹏、昇腾及 5G 能力）[8]。
- **龙头制造企业系**：海尔卡奥斯 COSMOPlat、三一根云（后独立为树根互联 RootCloud，已获腾讯参股）[10]。
- **软件服务商系**：用友精智、浪潮云洲等，依托传统 ERP/PLM 优势切入工业互联网。

国际市场上，早期以独立工业软件厂商为主导，如 GE Predix（现整合至 GE Vernova）、PTC ThingWorx、Rockwell FactoryTalk、Siemens MindSphere（已升级为 Xcelerator 生态）。近年来出现了向通用云厂商 IoT 基础设施"收编"的趋势：Google Cloud 已于 2023 年 8 月 16 日正式关闭 Cloud IoT Core 服务，转而依托合作伙伴生态提供设备连接能力 [15]；微软的 Azure Percept 边缘 AI 硬件套件也已于 2023 年 3 月 30 日停止服务 [14]，反映出通用云厂商在工业物联网垂直产品上的策略收缩与调整，转向以 Azure IoT Hub、Azure Digital Twins 等平台级能力 [13] 为核心，联合软硬件生态伙伴共同交付行业方案；AWS 则持续投入 IoT SiteWise、IoT TwinMaker、IoT Greengrass 等模块化服务 [11][12]，路径更为稳健。

### 2.3 商业模式

工业互联网平台的商业模式相较通用 PaaS 更为复杂，主要包括：

- **平台订阅/使用费**：按租户、按连接设备数或按数据吞吐量计费；
- **解决方案总包**：软件平台 + 硬件网关 + 实施服务打包收费，客单价高但交付周期长；
- **生态分成**：工业 APP 应用市场的上架与交易分成（如腾讯云 WeMake 平台层已沉淀 4900+ 工业 APP、5300+ 工业模型 [9]）；
- **政府补贴与示范项目**：区域级平台建设常与地方产业政策、专项补贴相结合。

### 2.4 市场面临的挑战

- 平台间同质化竞争明显，行业 Know-How（工艺机理模型）壁垒尚未充分沉淀；
- 缺乏统一的数据接口与标识解析标准，跨平台数据互通困难；
- 中小企业付费意愿和信息化投入能力有限，制约平台规模化变现；
- 工业数据安全与出境合规要求，使得国际厂商在国内工业场景的渗透率明显低于消费互联网领域。

## 三、技术调研

### 3.1 工业互联网整体技术架构

工业互联网的技术体系通常可分为三层：

- **边缘层**：负责设备接入、协议转换（OPC UA、Modbus、MQTT 等）与边缘侧实时计算，解决"最后一公里"联网与低时延处理问题；
- **平台层（IaaS/PaaS）**：提供计算与存储资源、应用托管能力（即实验二调研的通用应用级 PaaS）、IoT 设备管理、时序数据库、规则引擎/流计算、数字孪生建模、AI/大数据分析及低代码开发工具；
- **应用层**：面向具体业务的工业 APP，如 MES、APS 排产、能耗管理、预测性维护、供应链协同等。

通用应用级 PaaS（实验二调研对象）主要服务于平台层中"应用托管与运行"这一环节，而工业互联网场景还需要在其上叠加设备接入、边缘计算、数字孪生等工业专属能力，这也是本次调研相较实验二的延伸重点。

### 3.2 实验二结论在工业互联网场景下的再评估

实验二总结了通用应用级 PaaS 的若干共性特征，结合工业互联网场景的特殊性，可作如下再评估：

- **"缩容至零"与冷启动延迟**：实验二指出 Cloud Run、SAE 等 Serverless 型 PaaS 支持缩容至零但存在冷启动延迟。这一特性适合工业互联网中的报表生成、数据分析、低频 API 调用等非实时负载，但**不适合产线实时控制、安全联锁等对确定性时延要求极高的场景**——此类负载通常应下沉至边缘侧常驻运行，而非依赖云端 Serverless 弹性伸缩。
- **容器级 PaaS 与可移植性**：实验二认为容器级 PaaS（Cloud Run、SAE、腾讯云托管等）在可移植性上优于代码级 PaaS。在工业互联网场景中，企业往往采用"集团总部云 + 工厂本地私有化/边缘部署"的混合架构，容器化与开源标准（Kubernetes、Knative、OPC UA）的兼容性直接决定了应用能否在云边之间平滑迁移，这一优势被进一步放大。
- **供应商锁定风险**：实验二提到 SAE 深度集成阿里云 MSE、ARMS 等配套产品，锁定程度较高。在工业互联网场景下，企业通常需要长期（十年以上）稳定运行产线相关系统，供应商锁定风险的评估权重应高于一般互联网应用，这也是部分大型制造集团选择自建工业互联网平台、仅将云厂商 PaaS 作为底层基础设施的重要原因。

### 3.3 各云厂商工业互联网相关 PaaS 能力对比

在实验二"通用应用级 PaaS"对比的基础上，下表补充各厂商在工业互联网场景下的关键能力：

| 对比维度 | 阿里云 | 腾讯云 | 华为云 | AWS | Azure | Google Cloud |
|---|---|---|---|---|---|---|
| 通用应用 PaaS（承接实验二） | SAE | CloudBase / 云托管 | ServiceStage | Elastic Beanstalk / App Runner | App Service | App Engine / Cloud Run |
| 工业互联网专属平台 | supET（孵化犀牛智造）[6][7] | WeMake（原微瓴）[9] | FusionPlant [8] | 无独立工业互联网平台，以模块化 IoT 服务组合交付 | 无独立工业互联网平台，以 IoT Hub + Digital Twins 组合交付 | 无独立工业互联网平台，2023 年 8 月起关闭 IoT Core，转向合作伙伴生态 [15] |
| IoT 设备接入与管理 | Link IoT Edge / IoT 平台 | IoT Explorer / 微瓴 IoT | IoTDA 设备接入服务 | AWS IoT Core / IoT SiteWise [11] | Azure IoT Hub | 已关闭 Cloud IoT Core，需借助合作伙伴方案 [15] |
| 边缘计算能力 | Link IoT Edge | 边缘容器化（TKE Edge） | IEF 智能边缘平台 | IoT Greengrass [12] | Azure IoT Edge | 无原生对应服务（依赖第三方） |
| 数字孪生能力 | 供应链/产线数字孪生（依托 supET） | 平台层数字孪生（WeMake 2.0 新增）[9] | 依托华为云 GES 图引擎等能力构建 | IoT TwinMaker [11] | Azure Digital Twins（知识图谱建模）[13] | 无原生对应服务 |
| AI/预测性维护 | 工业大脑、PAI 机器学习平台 | 优图工业 AI [9] | 昇腾 AI + ModelArts | SageMaker + IoT SiteWise 异常检测 | Azure Machine Learning + IoT | Vertex AI（需自行对接设备数据） |
| 低代码工业 APP 开发 | 宜搭 / supET 应用市场 | 微搭 + WeMake 应用市场（4900+ 工业 APP）[9] | 华为云 AppCube | Honeycode（已停止新增功能）等第三方低代码生态 | Power Platform | AppSheet |
| 计费模式 | 平台订阅 + 底层资源按量 | 平台订阅 + 底层资源按量 | 平台订阅 + 底层资源按量 | 按 IoT 消息数/存储量/规则计费 | 按 IoT Hub 单元数/消息量计费 | 原按连接数计费，现服务已下线 |
| 境内合规与本地化 | 完善，支持等保、ICP 备案 | 完善，支持等保、ICP 备案 | 完善，面向政企国产化适配 | 中国区需独立账号，工业客户较少采用 | 中国区由世纪互联运营 | 中国大陆无节点 |

> 说明：Heroku 定位于通用 Web 应用托管，未提供面向工业物联网的设备接入、边缘计算或数字孪生能力，故未纳入本表对比，一般不适用于工业互联网场景。

### 3.4 技术选型建议

1. **大型制造集团**：建议采用"通用云厂商 IaaS/PaaS 基础设施 + 深度定制或自建工业互联网平台"的组合模式，如以华为云 FusionPlant、阿里云 supET 为底座叠加自身工艺 Know-How，兼顾弹性资源与数据主权。
2. **中小企业**：优先选择已具备行业模板、开箱即用的 SaaS 化平台（如卡奥斯 COSMOPlat、腾讯云 WeMake），降低实施门槛与前期投入。
3. **面向海外市场的企业**：可采用 AWS（IoT SiteWise + TwinMaker + Greengrass）或 Azure（IoT Hub + Digital Twins）的组合方案，但需注意 Google Cloud 已不再提供原生 IoT 设备接入服务，如涉及该平台需通过第三方合作伙伴弥补。
4. **架构设计原则**：应坚持"边缘处理实时性任务、云端处理分析与决策类任务"的云边协同原则，并优先选用支持开放协议（OPC UA）与容器化标准（Kubernetes）的平台，以降低长期供应商锁定风险。

## 四、总结与展望

工业互联网作为云计算在垂直行业落地的重点场景，其需求已从早期的"设备联网"逐步演进为涵盖数据采集、边缘计算、数字孪生、AI 预测性维护和低代码开发在内的综合能力体系。市场层面，国内已形成云计算厂商系、龙头制造企业系、软件服务商系三足鼎立的"双跨"平台格局，产业规模保持两位数增长；国际市场则呈现出通用云厂商收缩独立 IoT 硬件/平台产品线、转而依托合作伙伴生态与模块化云服务的趋势。

技术层面，实验二针对通用应用级 PaaS 得出的"容器化是主流方向""供应商锁定需纳入评估"等结论，在工业互联网场景中因其长生命周期、云边协同、高安全合规要求而进一步被放大；同时，产线实时控制类负载对 Serverless 缩容至零特性的适用性有限，需结合边缘部署加以弥补。

展望未来，随着工业大模型在质量检测、工艺参数优化等场景的应用探索，以及"5G+工业互联网"、"东数西算"对区域算力布局的持续影响，云计算厂商 PaaS 服务与工业互联网专属平台的边界有望进一步融合，为制造业数字化转型提供更加一体化的技术底座。
