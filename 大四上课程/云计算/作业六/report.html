一、概述与对比方法

云计算市场目前由 AWS、Microsoft Azure、Google Cloud 三家超大规模云厂商（Hyperscaler）主导，Oracle Cloud Infrastructure（OCI）凭借数据库与高性能 GPU 集群在 AI 时代快速增长，NVIDIA 则以 GPU 硬件、CUDA 软件栈和 DGX Cloud / NIM 等服务成为几乎所有 AI 云服务的底层供应者。本报告分两部分：

  • 任务一：选取计算、对象存储、无服务器、关系型数据库、NoSQL 五组功能相近的服务，从技术架构、性能、规模、收费、目标用户五个维度对 AWS、Google Cloud、Azure 进行横向对比，并为每组给出适合的实际应用场景。
  • 任务二：从AI 算力（芯片/实例）、机器学习平台、大模型服务、预置 AI API、智能体与开发工具、收费模式、目标用户等维度，对 AWS、Google Cloud、Microsoft、Oracle、NVIDIA 五家的 AI 服务进行对比。
说明：① 文中价格为各厂商官网公开目录价（美国东部 / us-central1 等基准区域、按需、美元）的参考量级，云厂商会频繁调价并存在区域差异，实际以官方价格计算器为准；② 部分产品近年更名（如 Cloud Functions → Cloud Run functions、SageMaker → SageMaker AI、Azure AI Foundry → Microsoft Foundry），文中以新名称为主并注明旧称；③ 题目示例中的 SimpleDB 已是 AWS 的遗留服务，新项目官方推荐 DynamoDB，故 NoSQL 组以 DynamoDB 为主、SimpleDB 作补充说明。

二、任务一：三大云服务组件对比

2.1 计算服务：Amazon EC2 vs Google Compute Engine vs Azure Virtual Machines

IaaS 虚拟机是云计算最基础的服务。三家都提供按需、预留/承诺、抢占式（Spot）三类计费，差异主要在虚拟化底座、实例灵活度与折扣机制。题目示例中的 GKE 属于容器编排层，因此在本组末尾补充托管 Kubernetes（EKS / GKE / AKS）的对比。

维度AWS EC2Google Compute EngineAzure Virtual Machines
技术架构基于 Nitro System：将网络、存储、管理功能卸载到专用 Nitro 卡，轻量 Nitro Hypervisor，接近裸金属性能；自研 ARM 处理器 Graviton（Graviton4）；存储挂载 EBS 块存储；VPC 网络 + 安全组。基于 KVM 加固的虚拟化和 Titanium 卸载架构；支持实时迁移（Live Migration），宿主机维护时虚拟机不中断；自研 ARM 处理器 Axion；全球 VPC（单个 VPC 可跨区域）；Persistent Disk / Hyperdisk。基于 Hyper-V 定制虚拟化，Azure Boost 将网络/存储卸载到专用硬件；自研 ARM 处理器 Cobalt 100；Managed Disks；VNet；与 Active Directory / Entra ID 深度集成。
性能实例族最丰富：通用 M/T、计算优化 C、内存优化 R/X/U、存储优化 I/D、加速 P/G/Inf/Trn；网络带宽最高可达数百 Gbps（EFA 支持 HPC/AI 集群）；Graviton 实例性价比通常比同代 x86 高约 20%–40%。E2/N2/N4（通用）、C3/C4（计算）、M3/M4（内存）、A3/A4（GPU）、H3（HPC）；独有自定义机器类型，可按需指定 vCPU 与内存比例，避免资源浪费；网络单 VM 最高 200 Gbps 级。B（突发）、D（通用）、E（内存）、F（计算）、M（超大内存，SAP HANA）、N（GPU）、H（HPC，InfiniBand）系列；Windows Server / SQL Server 工作负载优化突出。
规模全球区域与可用区数量最多（30+ 区域、100+ 可用区）；单实例最大可达数百 vCPU、数十 TB 内存（如 U7i 高内存实例）。40+ 区域、120+ 可用区；单 VM 最高数百 vCPU、数十 TB 内存（M 系列）；全球骨干网络是一大优势。60+ 区域（区域数最多），并有 Azure 中国（世纪互联运营）、政府云；单 VM 最大内存可达数十 TB（M 系列）。
收费按秒计费（Linux，最低 60 秒）；On-Demand、Savings Plans / Reserved Instances（1/3 年，最高约 72% 折扣）、Spot（最高约 90% 折扣，可能被回收）。参考：m7i.large（2 vCPU / 8 GiB）约 $0.10/小时。按秒计费（最低 1 分钟）；持续使用折扣（SUD）自动生效，无需预付；承诺使用折扣（CUD）最高约 55%–70%；Spot VM 约 60%–91% 折扣。参考：e2-standard-2（2 vCPU / 8 GB）约 $0.067/小时。按需计费；Reserved VM Instances（1/3 年，最高约 72%）、Savings Plan for Compute、Spot VM（最高约 90%）；Azure Hybrid Benefit 可复用本地 Windows/SQL Server 许可证，再省可观费用。参考：D2s v5（2 vCPU / 8 GiB）约 $0.096/小时。
目标用户各类规模企业与初创公司；需要最丰富实例选型、最成熟生态（Marketplace、第三方工具）的用户。数据密集型、容器化、云原生团队；希望“少运维、自动折扣”、对网络性能敏感的用户。以微软技术栈为主的传统企业（Windows、.NET、AD、SQL Server）；混合云（Azure Arc / Azure Stack）需求的政企客户。

补充：托管 Kubernetes（EKS vs GKE vs AKS）

维度Amazon EKSGoogle GKEAzure AKS
架构特点托管控制平面跨 3 个可用区；数据面可选 EC2 节点组、Fargate（无服务器 Pod）、EKS Auto Mode；节点扩缩可用 Karpenter。Kubernetes 源自 Google（Borg 经验）；Autopilot 模式下节点完全托管、按 Pod 资源计费；版本升级与集成最成熟。控制平面免费层可用；与 Entra ID、Azure Monitor、Azure DevOps / GitHub Actions 集成；支持 Windows 节点池。
规模单集群支持数千节点（AWS 已演示 10 万节点级超大集群用于 AI 训练）。Standard 集群最多 15,000 节点，Google 已演示 65,000 节点级集群。单集群最多约 5,000 节点。
收费控制平面 $0.10/小时/集群 + 节点费用。集群管理费 $0.10/小时（每个账单账号有一个免费额度）；Autopilot 按 Pod 申请的 vCPU/内存计费。Free 层控制平面免费；Standard 层（带 SLA）$0.10/小时/集群。
适用场景：① 电商“双11”/大促：日常用 Savings Plans/预留实例承载基线流量，大促时用 Auto Scaling + Spot 实例弹性扩容 Web 层（EC2 + ALB）；② 微服务 SaaS 平台：选择 GKE Autopilot，按 Pod 计费、免运维节点；③ 企业 ERP / .NET 应用上云：Azure VM + Azure Hybrid Benefit 复用原有 Windows 与 SQL Server 许可，迁移成本最低；④ 科学计算 / 渲染：GCE 自定义机型 + Spot VM 批量跑任务。

2.2 对象存储：Amazon S3 vs Google Cloud Storage vs Azure Blob Storage

维度Amazon S3Google Cloud StorageAzure Blob Storage
技术架构Bucket + Object 扁平命名空间，REST API（S3 API 已成为业界事实标准，MinIO、Ceph、各国内云均兼容）；数据默认跨 ≥3 个可用区冗余；2020 年起提供强读写一致性；S3 Express One Zone 提供单可用区高性能目录桶；新增 S3 Tables（Iceberg）、S3 Vectors。底层基于 Google 分布式文件系统 Colossus；位置类型分 region / dual-region / multi-region，dual-region 可选 Turbo Replication（15 分钟 RPO）；全局强一致性；同一套 API 访问所有存储类别，冷数据也毫秒级首字节。Storage Account → Container → Blob 三级结构；Blob 分 Block / Append / Page 三类（Page Blob 支撑虚拟机磁盘）；开启分层命名空间即为 ADLS Gen2，可当 HDFS 兼容数据湖使用；冗余选项 LRS / ZRS / GRS / RA-GRS / GZRS 可自由选择。
性能每个前缀可支撑 ≥3,500 次写 / 5,500 次读每秒，前缀数量不限，可线性扩展；Express One Zone 延迟个位数毫秒、比标准 S3 快约 10 倍；Transfer Acceleration 利用 CloudFront 边缘加速上传。自动按负载拆分键空间扩展吞吐；与 Google 全球网络、Cloud CDN 结合，跨洲访问性能好；支持 Anywhere Cache 等就近缓存。单个存储账户默认支持每秒约 2 万次请求级别、出口带宽数十至上百 Gbps；Premium Block Blob（SSD）提供低延迟；与 Azure Synapse / Fabric / Databricks 配合进行分析。
规模 / 可靠性设计持久性 99.999999999%（11 个 9）；存储数百万亿（数百 trillion）个对象；单对象传统上限 5 TB（2025 年底 AWS 宣布提升至 50 TB）。持久性 11 个 9；单对象上限 5 TiB；multi-region 可用性 SLA 99.95%。LRS 11 个 9、ZRS 12 个 9、GRS/GZRS 16 个 9；单个 Block Blob 最大约 190 TiB。
存储类别Standard、Intelligent-Tiering（自动分层）、Standard-IA、One Zone-IA、Glacier Instant / Flexible Retrieval、Glacier Deep Archive、Express One Zone。Standard、Nearline（≥30 天）、Coldline（≥90 天）、Archive（≥365 天）；Autoclass 自动分层。Hot、Cool（≥30 天）、Cold（≥90 天）、Archive（≥180 天，离线，需“解冻”数小时）；生命周期管理策略。
收费（参考）Standard 约 $0.023/GB·月；Deep Archive 约 $0.00099/GB·月；PUT $0.005/千次、GET $0.0004/千次；公网流出约 $0.09/GB（每月前 100 GB 免费）。Standard（单区域）约 $0.020/GB·月；Nearline $0.010、Coldline $0.004、Archive $0.0012；A 类操作约 $0.005/千次；流出约 $0.08–0.12/GB。Hot（LRS）约 $0.018/GB·月；Cool $0.010、Cold $0.0036、Archive 约 $0.00099；写操作约 $0.0055/万次级；流出约 $0.087/GB。
目标用户几乎所有云上用户：静态网站、数据湖、备份归档、AI 训练数据集；生态与第三方工具支持最广。大数据与 AI 用户（与 BigQuery、Vertex AI、Dataproc 无缝衔接）；需要多区域全局访问的内容分发场景。微软生态企业、需要 HDFS 兼容数据湖（ADLS Gen2）与 Microsoft Fabric、Power BI 分析的用户。
适用场景：① 短视频 / 图片平台：用户上传素材存 S3 Standard，配合 CloudFront 分发，30 天后由 Intelligent-Tiering 自动降级，降低 40% 以上存储成本；② AI 训练数据湖：原始数据放 GCS，直接被 BigQuery 外部表与 Vertex AI 训练读取；③ 企业合规归档（如银行影像、医疗 PACS）：Azure Blob 采用 GRS 冗余 + 不可变存储（WORM）策略，满足监管保存年限要求，长期数据转入 Archive 层。

2.3 无服务器计算：AWS Lambda vs Google Cloud Run functions vs Azure Functions

维度AWS LambdaCloud Run functions（原 Cloud Functions）Azure Functions
技术架构函数运行在 Firecracker 微虚拟机中，毫秒级启动且强隔离；事件源极多（S3、DynamoDB Streams、SQS、Kinesis、API Gateway、EventBridge 等 200+ 服务）；支持 ZIP 包或最大 10 GB 容器镜像；Step Functions 编排工作流。2024 年 Cloud Functions（第 2 代）并入 Cloud Run，底层为 Knative 风格容器平台；通过 Eventarc 接收 90+ 种事件源；单实例可并发处理多个请求（最高 1000），函数与容器服务可统一管理。基于 Azure App Service / WebJobs 运行时；独有触发器 + 绑定（Bindings）模型，少量代码即可读写 Blob、Cosmos DB、Service Bus；Durable Functions 支持有状态长流程编排；托管计划有 Flex Consumption、Premium、Dedicated 等。
性能与限制内存 128 MB–10,240 MB（CPU 按内存比例分配，最高 6 vCPU）；最长执行 15 分钟；默认每区域并发 1,000（可申请提高）；SnapStart、预置并发（Provisioned Concurrency）缓解冷启动。最高 8 vCPU / 32 GiB 内存；HTTP 函数最长 60 分钟，事件函数最长 9 分钟；最小实例数可消除冷启动；支持 GPU（Cloud Run GPU）。Flex Consumption：内存可选 512 MB–4 GB、可配置“常备实例”，最大可扩展到上千实例；旧 Consumption 计划最长 10 分钟，Premium/Flex 可更长；Premium 计划提供预热实例与 VNet 集成。
规模每秒可新增上千并发执行环境，单账号可扩展到数万并发；是最早（2014）且使用最广的 FaaS。自动扩缩到数千实例；依托 Cloud Run 统一的扩缩容与流量分割能力。Flex Consumption 单应用可扩展到 1,000 实例；与 Logic Apps 结合覆盖低代码集成场景。
收费（参考）$0.20/百万次请求 + 约 $0.0000166667/GB·秒（x86，ARM 便宜约 20%）；免费额度每月 100 万次请求 + 40 万 GB·秒。约 $0.40/百万次调用 + 按 vCPU·秒和 GiB·秒计费；免费额度每月 200 万次调用 + 18 万 vCPU·秒 + 36 万 GiB·秒；因可多并发共享实例，高并发 HTTP 场景往往更省。Consumption：$0.20/百万次执行 + $0.000016/GB·秒，免费每月 100 万次 + 40 万 GB·秒；Flex Consumption 按需实例 + 常备实例分别计费。
目标用户深度使用 AWS 的团队；事件驱动后端、数据管道、IoT、自动化运维。偏好容器和开放标准、希望函数与服务统一部署的开发者；Google 数据/AI 用户。.NET / C# 开发者、企业集成（Office 365、Dynamics、Service Bus）场景；需要有状态编排的业务流程。
适用场景：① 图片上传后自动生成缩略图 / 内容审核：S3 上传事件触发 Lambda 调用 Rekognition，结果写入 DynamoDB，零服务器运维、按次付费；② Webhook 与轻量 API（如支付回调、聊天机器人）：Cloud Run functions 高并发共享实例，冷启动少、费用低；③ 企业审批 / 订单流程：Azure Durable Functions 编排“提交→审批→通知→超时提醒”等长流程，并通过绑定直接写 Cosmos DB 与发送 Teams 消息。

2.4 关系型数据库：Amazon RDS / Aurora vs Cloud SQL / AlloyDB vs Azure SQL Database

维度Amazon RDS / AuroraCloud SQL / AlloyDB / SpannerAzure SQL Database（及 Azure Database for PostgreSQL/MySQL）
技术架构RDS：托管 MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2 共 6 种引擎，主备 Multi-AZ 同步复制 + 只读副本。Aurora：云原生“计算存储分离”，日志即数据库，数据在 3 个可用区写 6 副本；Aurora Serverless v2 自动伸缩；Aurora DSQL 提供分布式无服务器 SQL。Cloud SQL：托管 MySQL、PostgreSQL、SQL Server，区域级 HA（跨可用区同步复制）；Enterprise Plus 版带数据缓存。AlloyDB：兼容 PostgreSQL 的分离式架构 + 列式引擎，适合 HTAP。Spanner：基于 TrueTime 的全球分布式强一致数据库。Azure SQL Database：基于最新 SQL Server 引擎的 PaaS，提供 vCore 与 DTU 两种购买模型；General Purpose（远程存储）、Business Critical（本地 SSD + Always On 可用性组）、Hyperscale（日志服务 + 页服务器分离架构）三层；另有 SQL Managed Instance 及 PostgreSQL/MySQL Flexible Server。
性能RDS 可配 io2 存储达数十万级 IOPS；Aurora 官方称吞吐为标准 MySQL 的 5 倍、PostgreSQL 的 3 倍；副本延迟通常低于 100 ms。Cloud SQL Enterprise Plus 读性能显著提升；AlloyDB 官方称事务性能比标准 PostgreSQL 快 4 倍以上、分析查询快可达 100 倍。Business Critical 提供低延迟本地存储与内存 OLTP；Hyperscale 快速备份/恢复与秒级扩展只读副本；智能查询处理与自动调优。
规模RDS 单实例存储最大 64 TiB；Aurora 存储自动增长至 128 TiB 级，最多 15 个只读副本，Global Database 支持跨区域（秒级复制延迟）。Cloud SQL 最大 64 TB 存储、最多数十个读副本；Spanner 可水平扩展至 PB 级、提供 99.999% 可用性 SLA。Hyperscale 单库最大 128 TB；Business Critical 可用性 SLA 最高 99.995%；弹性池（Elastic Pool）托管大量小型租户库。
收费（参考）按实例小时 + 存储 + IOPS + 备份；小型实例如 db.t4g.micro 约 $0.016/小时；Aurora I/O-Optimized 可免 I/O 费用；预留实例最高约 60%+ 折扣。按 vCPU 与内存分别计费 + 存储（SSD 约 $0.17/GB·月）；HA 实例价格约为单实例 2 倍；CUD 1/3 年折扣 25%/52%。vCore 模型按 vCore 小时 + 存储；Serverless 计算层按秒计费并可空闲自动暂停；Azure Hybrid Benefit 复用 SQL Server 许可最高省约 55%；DTU 基本层每月数美元起。
目标用户需要多引擎选择、商用数据库（Oracle、SQL Server）上云的企业；高并发互联网业务选 Aurora。希望“开箱即用”的中小应用；需要 HTAP（AlloyDB）或全球一致性（Spanner）的金融、游戏、广告业务。使用 SQL Server 的企业及 .NET 应用；SaaS 多租户（弹性池）；需要与 Power BI / Fabric 联动的业务。
适用场景：① 电商订单与库存系统：Aurora MySQL 多可用区部署，读写分离 + 只读副本承载商品查询，Global Database 支持海外站点；② 全球化手游的账户与虚拟货币：Spanner 跨洲强一致事务，避免重复扣款；③ 企业内部 ERP / CRM 迁云：原 SQL Server 数据库通过 Azure Database Migration Service 迁移至 Azure SQL Managed Instance / SQL Database，兼容性最好并复用许可证；④ 中小型 Web 应用 / 校园系统：Cloud SQL for PostgreSQL 单实例起步，按需开启 HA。

2.5 NoSQL 数据库：Amazon DynamoDB（SimpleDB）vs Google Bigtable vs Azure Cosmos DB

维度Amazon DynamoDB（附：SimpleDB）Google Cloud BigtableAzure Cosmos DB
数据模型 / 架构键值 + 文档模型，按分区键哈希自动分片，每个分区 3 副本跨可用区；完全无服务器，无需管理节点；DynamoDB Streams 捕获变更；Global Tables 多区域多活（支持多区域强一致）；DAX 内存缓存达微秒级。

3.2 重点分析

（1）算力之争：GPU vs 自研芯片

NVIDIA GPU 仍是训练大模型的主流选择，四家云厂商都提供最新的 Hopper/Blackwell 实例。但为降低成本与供应依赖，AWS（Trainium/Inferentia）、Google（TPU）、Microsoft（Maia）都在推进自研加速器：Google TPU 最为成熟，Gemini 系列即在 TPU 上训练；AWS Trainium 被 Anthropic 等大规模采用。Oracle 不做自研芯片，而是同时采购 NVIDIA 与 AMD GPU，以超大集群规模与低网络费用取胜。NVIDIA 则通过 NVLink、InfiniBand 等互联技术和 CUDA 软件生态构建护城河。

（2）大模型平台：开放模型市场 vs 自研/独家模型

AWS Bedrock 强调“模型中立”，提供多家第三方模型和自研 Nova；Google Vertex AI 以自研 Gemini 为核心并开放 Model Garden；Microsoft 依托与 OpenAI 的深度合作，在 Foundry 中提供 GPT 系列并扩展到其他模型；Oracle 将生成式 AI 与数据库（AI Vector Search）及 Fusion 企业应用结合；NVIDIA 通过 NIM 把模型推理“容器化”，可部署在任何云或本地数据中心，满足数据不出域的需求。

（3）收费差异

大模型 API 普遍按输入/输出 Token 计费，输出价格通常是输入的 3–5 倍；高稳定性需求可购买预置吞吐（AWS Provisioned Throughput、Azure PTU）；离线任务可用批处理获得约 50% 折扣。算力层面，按需 GPU 价格高且紧缺，长期训练更适合预约容量或 1–3 年承诺。NVIDIA 采用软件订阅（AI Enterprise）+ 云上算力租赁的模式。

4.2 选型建议

  • 按现有技术栈选：Windows、.NET、SQL Server、Microsoft 365 用户优先 Azure；数据分析与 AI 驱动型团队优先 Google Cloud；需要最丰富服务与生态的通用场景优先 AWS；核心系统运行在 Oracle 数据库 / ERP 上的企业可考虑 OCI。
  • 按工作负载特征选：海量写入 + 范围扫描用 Bigtable；高并发键值访问用 DynamoDB；全球多活 + 多模型用 Cosmos DB；全球强一致事务用 Spanner。
  • 按成本选：稳定负载用预留/承诺折扣，弹性批处理用 Spot；对象存储开启自动分层；无服务器适合低频/突发流量，持续高负载时容器或虚拟机更便宜；警惕数据流出费用（Egress），这是多云架构中最容易被忽视的成本。
  • 避免锁定：优先采用 Kubernetes、S3 兼容 API、PostgreSQL、开放模型与 NIM 等开放标准，必要时采用多云 / 混合云策略。

五、总结

通过对比可以看出，三大云在核心服务上功能高度趋同，但设计理念各有侧重：AWS 以“服务最全、生态最大”见长，S3、Lambda、DynamoDB 等多项服务开创了行业品类；Google Cloud 将内部基础设施（Borg、Colossus、Bigtable、Spanner、TPU）产品化，在容器、大数据与 AI 方面技术领先；Azure 以企业市场和微软软件生态为核心，在混合云和办公 AI 落地方面最具优势。AI 领域中，Oracle 依托数据库和 GPU 超大集群快速崛起，NVIDIA 则掌握算力与软件栈底层，是所有云 AI 服务的共同基础。实际选型不存在“最好”的云，应结合业务场景、团队技能、成本结构与合规要求综合决策。
