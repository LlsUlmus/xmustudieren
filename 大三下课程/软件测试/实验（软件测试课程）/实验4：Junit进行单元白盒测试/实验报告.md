## 三、被测程序

### 3.1 程序代码

```java
if (A > 1 && B == 0)
    X = X / A;
if (A == 2 || X > 1)
    X = X + 1;
return X;
```

### 3.2 程序说明

- 输入：整型变量 A、B、X
- 输出：经过逻辑运算后的 X
- 判定1：`A > 1 && B == 0`，条件为真时执行 `X = X / A`
- 判定2：`A == 2 || X > 1`，条件为真时执行 `X = X + 1`
- 整数除法：`X / A` 的结果取整

### 3.3 条件分解

| 编号 | 条件 | 含义 |
|------|------|------|
| C1 | A > 1 | 第一个条件的左子条件 |
| C2 | B == 0 | 第一个条件的右子条件 |
| C3 | A == 2 | 第二个条件的左子条件 |
| C4 | X > 1 | 第二个条件的右子条件 |

### 3.4 程序控制流图

```
        [开始]
           |
           v
    +------------------+
    |  C1 && C2 ?      |  判定1
    +------------------+
      |真          |假
      v            |
  X = X / A        |
      |            |
      +-----+------+
            v
    +------------------+
    |  C3 || C4 ?      |  判定2
    +------------------+
      |真          |假
      v            |
  X = X + 1        |
      |            |
      +-----+------+
            v
        [return X]
           |
           v
        [结束]
```

## 四、覆盖标准与测试用例设计

### 4.1 语句覆盖

**定义：** 设计测试用例，使程序中每条可执行语句至少被执行一次。

**设计思路：** 只需一条用例同时进入两个 if 分支即可覆盖全部语句。

| 用例 | A | B | X | 执行过程 | 期望 R |
|------|---|---|---|----------|--------|
| TC1 | 2 | 0 | 3 | 判定1真：X=3/2=1；判定2真(A=2)：X=2 | 2 |

**覆盖语句：** `X=X/A`、`X=X+1`、`return X` 均被覆盖。

---

### 4.2 分支覆盖

**定义：** 每个判定的真假分支至少各执行一次。

| 用例 | A | B | X | 判定1 | 判定2 | 期望 R |
|------|---|---|---|-------|-------|--------|
| TC1 | 2 | 0 | 3 | 真 | 真 | 2 |
| TC2 | 1 | 0 | 1 | 假 | 假 | 1 |
| TC3 | 3 | 0 | 3 | 真 | 假 | 1 |
| TC4 | 2 | 1 | 2 | 假 | 真 | 3 |

**说明：**

- TC1：两个判定均为真
- TC2：两个判定均为假
- TC3：判定1真，判定2假（A≠2 且 X=1 不大于 1）
- TC4：判定1假（B≠0），判定2真（A=2）

---

### 4.3 条件覆盖

**定义：** 每个条件的真假值至少各出现一次。

| 用例 | A | B | X | C1 | C2 | C3 | C4 | 期望 R |
|------|---|---|---|----|----|----|----|--------|
| TC1 | 2 | 0 | 3 | T | T | T | - | 2 |
| TC2 | 1 | 0 | 1 | F | T | F | F | 1 |
| TC3 | 2 | 1 | 1 | T | F | T | - | 2 |

**说明：**

- C1(A>1)：TC1 为真，TC2 为假
- C2(B==0)：TC1、TC2 为真，TC3 为假
- C3(A==2)：TC1、TC3 为真，TC2 为假
- C4(X>1)：TC2 中为假；当 A=2 时由于短路求值，C4 可能不被计算

---

### 4.4 分支-条件覆盖

**定义：** 同时满足分支覆盖和条件覆盖的要求。

| 用例 | A | B | X | 判定1 | 判定2 | 期望 R |
|------|---|---|---|-------|-------|--------|
| TC1 | 2 | 0 | 3 | 真 | 真 | 2 |
| TC2 | 1 | 0 | 1 | 假 | 假 | 1 |
| TC3 | 2 | 1 | 1 | 假 | 真 | 2 |
| TC4 | 3 | 0 | 1 | 真 | 假 | 0 |

**说明：** 四条用例组合后，各条件的真假值及两个判定的真假分支均被覆盖。

---

### 4.5 路径覆盖

**定义：** 覆盖程序的主要执行路径组合。

| 路径编号 | 路径描述 | 用例(A,B,X) | 期望 R |
|----------|----------|-------------|--------|
| P1 | 判定1真 → X=X/A → 判定2真 | (2,0,3) | 2 |
| P2 | 判定1假 → 判定2假 | (1,0,1) | 1 |
| P3 | 判定1假 → 判定2真 | (2,1,1) | 2 |
| P4 | 判定1真 → X=X/A → 判定2假 | (3,0,1) | 0 |

## 五、JUnit 测试代码设计

### 5.1 测试类与覆盖标准对应关系

| 测试类 | 覆盖标准 | 测试方法 |
|--------|----------|----------|
| StateTest | 语句覆盖 | testStatementCoverage |
| BranchTest | 分支覆盖 | testBranchCoverage1、testBranchCoverage2 |
| ConditionTest | 条件覆盖 | testConditionCoverage |
| BranchConditionTest | 分支-条件覆盖 | testBranchConditionCoverage1、testBranchConditionCoverage2 |
| PathTest | 路径覆盖 | testPathCoverage |

### 5.2 测试套装

使用 `ExamTestSuite3.java` 将以上 5 个测试类装入 TestSuite，统一执行：

```java
public static Test suite() {
    TestSuite suite = new TestSuite(ExamTestSuite3.class.getName());
    suite.addTestSuite(StateTest.class);
    suite.addTestSuite(BranchTest.class);
    suite.addTestSuite(ConditionTest.class);
    suite.addTestSuite(BranchConditionTest.class);
    suite.addTestSuite(PathTest.class);
    return suite;
}
```

## 八、实验小结

1. 通过本次实验，掌握了白盒测试中五种常用覆盖标准的基本含义和用例设计方法。
2. 语句覆盖要求最低，通常用较少用例即可实现；分支覆盖、条件覆盖要求逐步提高；分支-条件覆盖和路径覆盖对用例设计的要求更高。
3. 对于含有 `&&` 和 `||` 的复合条件，应注意 Java 的**短路求值**规则，某些子条件在特定情况下不会被计算。
4. 使用 JUnit3 的 `TestCase` 可方便地组织 `setUp`、测试方法和断言；使用 `TestSuite` 可将多类测试统一执行，便于批量测试。
5. 白盒测试从程序内部逻辑出发设计用例，与黑盒测试互补，有助于发现逻辑分支中的缺陷。
