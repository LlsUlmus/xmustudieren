## 五、测试场景设计

设置**两个用户场景**，并监测 JMeter 指标与服务器 JVM 资源。

### 场景1：性能测试（基准负载）

| 参数 | 值 |
|------|-----|
| 并发用户数 | 15 |
| Ramp-Up | 10 秒 |
| 循环次数 | 20 |
| 总请求数 | 300 |
| 目的 | 模拟日常业务负载，建立性能基线 |

### 场景2：压力测试（高并发）

| 参数 | 值 |
|------|-----|
| 并发用户数 | 50 |
| Ramp-Up | 5 秒 |
| 循环次数 | 30 |
| 总请求数 | 1500 |
| 目的 | 持续高并发施压，观察吞吐与响应时间变化 |

### 监测指标

- **JMeter**：响应时间（平均/P90/P95/P99）、吞吐量(TPS)、错误率、Connect、Latency  
- **时间分解**：连接时间、网络/等待时间(Latency−Connect)、下载时间(Elapsed−Latency)  
- **服务器**：JVM 进程 CPU 使用率、工作集内存(MB)

## 七、瓶颈分类分析

### 7.1 场景1 瓶颈分类

| 类别 | 严重程度 | 分析 |
|------|----------|------|
| 网络连接 | 低 | Connect 均值 0.1ms，Keep-Alive 复用连接，非瓶颈 |
| 服务器处理 | 低 | 首字节等待约 1.5ms，Spring Boot 处理极快 |
| 下载/传输 | 低 | JSON 体积极小，下载时间可忽略 |
| CPU 资源 | 中 | JVM CPU 峰值约 90%，含 Gradle 启动后 JVM 预热因素 |
| 内存 | 低~中 | 压测期间增长约 233MB，主要为 JVM 堆正常扩张，未见持续泄漏 |
| 功能/稳定性 | 低 | 错误率 0%，全部检查点通过 |

**小结**：整体性能良好，无明显架构瓶颈；延迟主要在网络/等待首字节阶段，绝对值极低。

---

### 7.2 场景2 瓶颈分类

| 类别 | 严重程度 | 分析 |
|------|----------|------|
| 网络连接 | 低 | Connect 均值 0.06ms，高并发下连接仍非瓶颈 |
| 服务器处理 | 低 | 首字节等待约 0.64ms，甚至比场景1更低（连接池/JIT 预热） |
| 下载/传输 | 低 | 下载时间 < 0.01ms |
| CPU 资源 | 中 | JVM CPU 峰值约 93%，负载升高但仍可支撑 |
| 内存 | 低~中 | 增长约 220MB，趋势与场景1一致，无异常泄漏迹象 |
| 功能/稳定性 | 低 | 1500 次请求全部成功，检查点通过 |

**小结**：50 并发、1500 请求压力下系统仍稳定；若继续加大并发，需重点关注 CPU 与 Tomcat 线程池配置。

## 九、实验结论

1. 本次实验使用 JMeter 对 Spring Boot REST 接口 `/greeting` 完成了**脚本增强**（事务、参数化、检查点）及**双场景**性能测试。  
2. 场景1（300 请求）与场景2（1500 请求）**错误率均为 0%**，功能正确性得到验证。  
3. 时间分析表明：响应延迟集中在**首字节等待**阶段，连接与下载时间可忽略；两场景 P95 均在 3ms 以内。  
4. 服务器资源方面，JVM 内存随测试有一定增长，属正常运行范围；CPU 在压测窗口内升高但未导致超时或错误。  
5. 该示例服务为轻量级接口，当前测试规模下**未暴露明显性能瓶颈**；若用于真实业务，应结合更复杂业务逻辑、数据库访问及更长疲劳测试进一步评估。
