# 作业15：透明装饰模式与半透明装饰模式

## 一、概念说明

### 1. 透明装饰模式（Transparent Decorator）

**定义**：具体组件与所有装饰器都继承（或实现）同一个抽象组件类型，客户端**始终通过该抽象类型**访问对象，可以在运行时用装饰器层层包装，而**不必关心**当前对象是原始组件还是某一层装饰器。

**特点**：
- 装饰器不向外暴露“只有本层才懂”的新接口；
- 支持无限嵌套包装，客户端代码更统一；
- 典型实现：装饰器与组件**同继承体系**（如都继承 `Beverage`）。

**本作业示例**：`transparent` 包中的咖啡加料。客户端只用 `Beverage` 变量，依次 `new Milk(new Sugar(new Espresso()))`，只调用 `getDescription()` 和 `cost()`。

### 2. 半透明装饰模式（Semi-transparent Decorator）

**定义**：装饰器在实现组件接口的同时，**额外提供**仅属于该装饰器的能力。客户端若只持有组件接口，只能使用通用方法；若要使用增强能力，必须**知道并转型**为具体装饰器类型。

**特点**：
- 接口更干净，但类型信息部分“泄漏”给客户端；
- 适合“大部分调用方只需通用行为，少数需要专用能力”的场景。

**本作业示例**：`decorator` 包中的 `JsonParsingDecorator`。它实现 `HttpRequestHandler.handleRequest`，还提供 `getJsonField(String)`。`DecoratorMain` 中必须保留 `JsonParsingDecorator` 引用才能读取解析后的字段。

### 3. 对比小结

| 维度 | 透明装饰 | 半透明装饰 |
|------|----------|------------|
| 客户端类型 | 始终用抽象组件类型 | 常用接口，必要时用具体装饰器 |
| 新增方法 | 一般不增加 | 装饰器可有专有方法 |
| 灵活性 | 包装链更自由 | 专用功能需显式类型 |
| 示例 | 咖啡加牛奶、糖 | JSON 解析后按字段读取 |

## 二、项目结构

```
作业15/
├── src/
│   ├── decorator/          # 半透明：HTTP 请求装饰链
│   ├── transparent/      # 透明：饮品加料
│   └── reflection/       # 反射：setProperty、浅拷贝
└── 作业说明.md
```

## 三、编译与运行

在项目根目录执行：

```bash
javac -encoding UTF-8 -d out src/decorator/*.java src/transparent/*.java src/reflection/*.java
java -cp out decorator.DecoratorMain
java -cp out transparent.TransparentMain
java -cp out reflection.ReflectionMain
```

将控制台输出截图，连同本说明中的源码一并放入 Word 文档提交。
