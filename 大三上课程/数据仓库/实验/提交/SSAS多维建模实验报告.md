# SQL Server Analysis Services (SSAS) 多维建模实验报告

## 1. 实验环境
- SQL Server 2019
- SQL Server Analysis Services (SSAS)
- SQL Server Data Tools (SSDT)

## 2. 实验目的
（1）掌握在Analysis Services的SQL Server Data Tools项目中定义数据源、数据源视图、维度、属性、属性关系、层次结构和多维数据集。

（2）掌握如何通过将 Analysis Services项目部署到Analysis Services实例来查看多维数据集和维度数据，以及如何在随后处理已部署对象以便使用基础数据源中的数据来填充对象。

## 3. 实验内容和步骤

### 第1课：在Analysis Services项目中定义数据源视图

#### 3.1 创建Analysis Services项目

**步骤：**
1. 打开SQL Server Data Tools (SSDT)
2. 选择"文件" → "新建" → "项目"
3. 在"新建项目"对话框中，选择"商业智能" → "Analysis Services" → "Analysis Services多维和数据挖掘项目"
4. 将项目命名为"Adventure Works Tutorial"
5. 选择适当的位置并创建项目

**关键点：**
- 使用Analysis Services多维模型模板
- 项目将包含所有解决方案元素

#### 3.2 定义数据源

**步骤：**
1. 在解决方案资源管理器中，右键单击"数据源"文件夹
2. 选择"新建数据源"
3. 在数据源向导中：
   - 选择"新建"创建新连接
   - 在"连接管理器"中：
     - 服务器名称：输入SQL Server实例名称
     - 选择"使用Windows身份验证"
     - 在"选择或输入数据库名称"下拉列表中选择"AdventureWorksDW2019"
   - 测试连接确保成功
   - 完成连接创建

**重要说明：**
- 将AdventureWorksDW2019改为实际的数据库名称
- 确保数据库连接正常
- 使用适当的身份验证方法

#### 3.3 定义数据源视图

**步骤：**
1. 在解决方案资源管理器中，右键单击"数据源视图"文件夹
2. 选择"新建数据源视图"
3. 在数据源视图向导中：
   - 选择刚创建的数据源
   - 在"选择表和视图"页面中，选择以下表：
     - FactInternetSales
     - DimProduct
     - DimDate
     - DimCustomer
     - DimGeography
     - DimSalesTerritory
     - DimProductCategory
     - DimProductSubcategory
   - 完成数据源视图创建

**关键功能：**
- 提供统一的元数据视图
- 支持表间关系定义
- 允许重命名表和列

#### 3.4 修改默认表名

**步骤：**
1. 在数据源视图设计器中，选择表
2. 右键单击表名，选择"重命名"
3. 将表名修改为更友好的名称：
   - FactInternetSales → Internet Sales
   - DimProduct → Product
   - DimDate → Date
   - DimCustomer → Customer
   - DimGeography → Geography
   - DimSalesTerritory → Sales Territory
   - DimProductCategory → Product Category
   - DimProductSubcategory → Product Subcategory

### 第2课：定义和部署多维数据集

#### 3.5 创建多维数据集

**步骤：**
1. 在解决方案资源管理器中，右键单击"多维数据集"文件夹
2. 选择"新建多维数据集"
3. 在多维数据集向导中：
   - 选择"使用现有表"
   - 选择"Internet Sales"事实表
   - 选择度量值组：Internet Sales
   - 选择度量值：Sales Amount, Order Quantity, Unit Price等
   - 选择相关维度：Product, Date, Customer, Sales Territory
   - 完成多维数据集创建

**关键组件：**
- 事实表：包含度量值数据
- 维度表：提供分析角度
- 度量值：可聚合的数值数据

#### 3.6 部署多维数据集

**步骤：**
1. 在解决方案资源管理器中，右键单击项目名称
2. 选择"属性"
3. 在"部署"选项卡中：
   - 设置服务器名称
   - 设置数据库名称
4. 右键单击项目，选择"部署"
5. 在部署进度窗口中查看部署状态

**部署验证：**
- 检查部署是否成功
- 验证多维数据集是否在SSAS实例中可见
- 测试连接和查询功能

### 第3课：修改度量值、属性和层次结构

#### 3.7 修改度量值

**步骤：**
1. 在多维数据集设计器中，选择"度量值"选项卡
2. 选择要修改的度量值
3. 在属性窗口中修改：
   - 名称：更友好的显示名称
   - 格式：设置数字格式
   - 聚合函数：Sum, Count, Average等
   - 可见性：控制是否在客户端显示

**示例修改：**
- Sales Amount → 销售额
- Order Quantity → 订单数量
- Unit Price → 单价

#### 3.8 修改属性

**步骤：**
1. 在多维数据集设计器中，选择"维度"选项卡
2. 展开维度，选择属性
3. 在属性窗口中修改：
   - 名称：显示名称
   - 键列：指定唯一标识符
   - 名称列：指定显示名称
   - 排序：设置排序方式
   - 可见性：控制显示状态

**示例修改：**
- ProductKey → 产品ID
- ProductName → 产品名称
- Color → 颜色

#### 3.9 创建层次结构

**步骤：**
1. 在维度设计器中，选择"层次结构"选项卡
2. 将属性拖拽到层次结构区域
3. 按逻辑顺序排列属性：
   - 产品类别 → 产品子类别 → 产品名称
   - 年份 → 季度 → 月份 → 日期
4. 设置层次结构属性：
   - 名称：层次结构名称
   - 可见性：控制显示状态

**示例层次结构：**
- 产品层次结构：类别 → 子类别 → 产品
- 时间层次结构：年 → 季度 → 月 → 日
- 地理层次结构：国家 → 地区 → 城市

#### 3.10 定义属性关系

**步骤：**
1. 在维度设计器中，选择"属性关系"选项卡
2. 创建属性间的关系：
   - 产品子类别 → 产品类别
   - 月份 → 季度
   - 季度 → 年份
3. 设置关系属性：
   - 关系类型：刚性或柔性
   - 可见性：控制关系显示

3. **数据源视图构建**：创建了包含8个核心表的数据源视图，建立了表间关系，并优化了表名显示。

4. **多维数据集设计**：基于Internet Sales事实表和相关维度表创建了多维数据集，定义了关键度量值。

5. **项目部署**：成功将项目部署到Analysis Services实例，验证了部署的正确性。

6. **对象优化**：修改了度量值、属性和层次结构，提高了用户友好性和分析效率。

### 4.2 对实验的认识

1. **多维建模的重要性**：通过本实验深入理解了OLAP多维建模的核心概念，包括事实表、维度表、度量值、属性等关键组件。

2. **SSAS的强大功能**：SQL Server Analysis Services提供了完整的多维数据建模和部署解决方案，支持复杂的商业智能分析需求。

3. **数据源视图的价值**：数据源视图作为元数据层，提供了统一的数据访问接口，屏蔽了底层数据源的复杂性。

4. **层次结构的作用**：层次结构是OLAP分析的核心，提供了从粗粒度到细粒度的分析路径，支持钻取和上卷操作。

5. **部署和处理的流程**：理解了从开发到生产的完整流程，包括项目部署、对象处理等关键步骤。

### 4.3 遇到的问题及解决方法

1. **数据库连接问题**
   - 问题：初始连接AdventureWorksDW2019数据库失败
   - 解决方法：检查SQL Server服务状态，确认数据库存在，使用正确的身份验证方式

2. **表关系定义问题**
   - 问题：在数据源视图中表间关系不明确
   - 解决方法：仔细分析表结构，根据外键关系手动创建表间关联

3. **度量值聚合问题**
   - 问题：某些度量值的聚合方式不合适
   - 解决方法：根据业务逻辑选择合适的聚合函数（Sum、Count、Average等）

4. **层次结构设计问题**
   - 问题：层次结构设计不符合业务分析需求
   - 解决方法：与业务用户沟通，重新设计层次结构，确保符合实际分析场景

5. **部署权限问题**
   - 问题：部署到Analysis Services实例时权限不足
   - 解决方法：确保当前用户具有Analysis Services管理员权限，或联系系统管理员授权
